# Railsベクター検索デモ 要件定義書

**作成日**: 2026年5月6日
**更新日**: 2026年5月6日

## 1. 機能概要

Railsアプリケーションにベクター検索機能を統合する方法を解説する技術記事の題材として、ブログ記事の類似検索デモアプリを構築する。読者がリポジトリをクローンしてローカルで動作させ、コードを読みながら理解できる小規模なRailsアプリを成果物とする。

**主要な提供価値**:

- Railsの標準的な機能（CRUD、ActiveJob、Hotwire等）とベクター検索の組み合わせ方の例示
- ベクター検索の基本概念（埋め込みベクトル、類似度、検索）の動作する形での提示
- 完全にローカルで動作する構成による、読者の追体験のしやすさ

**想定データ規模**:

- ブログ記事: 20〜50件（seedで初期投入、デモ中の追加・編集も可能）

**利用者**:

- 単一ロールの利用者を想定する（認証・権限分離はスコープ外。誰でも全機能にアクセスできる）。

## 2. 機能要件

### 2.1 基本処理フロー

#### 2.1.1 ブログ記事の管理

1. **記事の閲覧**
   - 利用者は記事一覧画面で投稿済みのブログ記事を閲覧できる
   - 利用者は記事詳細画面で個別記事の内容を閲覧できる

2. **記事のCRUD**
   - 利用者は新規記事を作成できる
   - 利用者は既存記事を編集できる
   - 利用者は既存記事を削除できる
   - 記事に保持する属性は「タイトル」と「本文」のみとする

3. **埋め込みベクトルの生成・更新**
   - 記事の作成・更新が確定したタイミングで、対象記事の埋め込みベクトルを非同期で生成・更新する
   - 利用者の記事保存操作は、埋め込みベクトル生成の完了を待たずに完了する
   - 記事削除時には、対応する埋め込みベクトルも削除する

#### 2.1.2 類似記事の検索

1. **クエリ文による類似記事の一覧表示**
   - 利用者は専用の検索画面でクエリ文（短いキーワードまたは質問文）を入力できる
   - 入力されたクエリ文に類似する記事が、類似度の高い順に上位件数まで表示される
   - 検索結果の表示項目は記事タイトルとする
   - 表示件数（top-K）は機能設計書で定める

2. **記事詳細からの類似記事提示**
   - 記事詳細画面に「類似記事」セクションを設け、当該記事に類似する他記事を上位件数まで表示する
   - 表示対象から閲覧中の記事自体は除外する
   - 表示項目は記事タイトルとする
   - 表示件数は機能設計書で定める

### 2.2 データ仕様

- **データソース**: 本デモアプリ自身のデータベース
- **初期データ**: 開発環境構築時にseedとして20〜50件程度のブログ記事を投入する
- **データ取得要件**:
  - 記事一覧では全件を取得する（デモ規模ではページング不要とする）
  - 類似記事検索では、クエリ文の埋め込みベクトルと既存記事の埋め込みベクトルの類似度に基づいて並び替えた結果を返す
  - 類似度指標の具体（コサイン類似度／内積／ユークリッド距離 等）はADRで決定する

### 2.3 エラー処理

- **エラー条件**:
  - 埋め込みベクトル生成の非同期処理が失敗した場合: 記事自体は保存済みとし、ActiveJob 標準の `retry_on` による自動再試行を行う。最終的に失敗した場合は当該記事の埋め込みベクトルが未生成のままとなり、検索結果には含まれない
  - クエリ文が空の場合: 検索を実行せず、入力を促す表示にとどめる
- **エラー通知**:
  - 記事保存時のバリデーションエラーは利用者に画面上で通知する
  - 埋め込みベクトル生成ジョブの失敗を画面で通知する仕組みは設けない（スコープ外）

## 3. 前提条件・制約事項

### 3.1 前提条件

- **システム前提条件**:
  - 開発・実行環境としてDocker Composeが利用できること（READMEで前提を明示する）
- **データ前提条件**:
  - seed投入されるブログ記事は、類似検索の動作確認に足りる多様性を持たせる（受入条件で動作確認可能であること）

### 3.2 制約事項

- **技術的制約**:
  - Rails / Ruby は最新安定版を使用する
  - フロントエンドは Hotwire（Turbo + Stimulus）を採用する
  - 埋め込みベクトル生成および類似度計算を含む全機能が、外部APIに依存せずローカルで完結すること
  - 埋め込みベクトル生成は ActiveJob による非同期実行とすること
- **業務上の制約**:
  - コードの説明しやすさを最優先とする（記事執筆時に引用しやすいファイル構成・コミット粒度を意識する）
- **公開条件**:
  - 成果物のリポジトリは GitHub で OSS として公開する
  - READMEに、クローンからセットアップ・起動までの手順を記載する

### 3.3 依存関係

- 本デモアプリは独立して動作する。外部サービス連携・既存システム依存はない。

### 3.4 未決事項（ADRで決定する）

本要件定義書時点で未決定であり、Phase 5 のADRで決定する事項:

- 採用する埋め込みモデル（ローカル動作可能なもののうちどれを使用するか）
- 採用するベクターDB（pgvector 等のRDB拡張、または専用ベクターDBのいずれか。「ローカル完結」「外部サービス連携なし」の制約を満たすもの）
- 類似度指標（コサイン類似度／内積／ユークリッド距離 等）
- Rails / Ruby の具体バージョン
- Rails と上記ベクターDB・埋め込みモデルを橋渡しする実装方式（gemの選定を含む）

## 4. 用語定義

| 用語 | 説明 |
|------|------|
| ベクター検索 | クエリ文と対象データを高次元ベクトルに変換し、ベクトル間の類似度で検索する手法 |
| 埋め込みベクトル (embedding) | テキスト等の情報を意味的な特徴を保持した固定長の数値ベクトルに変換した結果 |
| 埋め込みモデル | テキストを埋め込みベクトルに変換するモデル（本デモではローカル動作のものを採用する） |
| 類似度 | 2つのベクトル間の近さを表す指標。コサイン類似度・内積・ユークリッド距離等が用いられる |
| ベクターDB | 埋め込みベクトルを格納し、類似度に基づく検索を効率的に実行できるデータストア |
| 類似記事 | クエリ文または特定の記事に対して、埋め込みベクトル空間上で近い位置にある記事 |
| クエリ文 | 利用者が類似記事検索のために入力する短いキーワードまたは質問文 |
| top-K | 類似度の高い上位K件を返す検索方式 |
| 非同期実行 | 利用者の操作完了とは独立に、バックグラウンドで処理を実行する方式 |
| seed | 開発・テスト用にデータベースへ投入する初期データ |
| 追体験 | 読者がリポジトリをクローンして同じ環境を再現し、自分で動作確認を行うこと |

## 5. 受け入れ条件

- [ ] ブログ記事の作成・更新・削除・閲覧（一覧・詳細）が機能すること
- [ ] 記事の作成・更新時に、埋め込みベクトルが非同期で生成・更新されること
- [ ] 記事の削除時に、対応する埋め込みベクトルが削除されること
- [ ] 埋め込みベクトル生成ジョブの失敗時に ActiveJob の `retry_on` による再試行が動作すること
- [ ] クエリ文を入力して、類似記事の一覧を上位件数まで類似度順で取得できること
- [ ] 記事詳細画面に類似記事セクションが表示され、当該記事自身は除外されること
- [ ] seed投入後、上記検索が「明らかに関連する記事が上位に来る」形で動作確認できること（類似検索が機能していると判断できる程度の結果差が出ること）
- [ ] 完全にローカルで動作し、外部API認証情報なしで全機能が利用できること
- [ ] READMEの手順に従い、第三者が開発環境を構築できること

## 6. スコープ外（明示的な対象外事項）

以下は本デモのスコープに含めない。

- 認証・認可・多テナント機能
- 本番運用レベルのインフラ構成（Kubernetes、監視、スケール設計、ログ集約等）
- RAG（LLMによる回答生成）
- 全文検索（キーワード検索・BM25 等）との併用、およびハイブリッド検索の高度なチューニング（RRF、スコア正規化の詳細調整等）
- 大規模データセット（数万件以上）の取り込みと運用
- 検索結果のハイライト表示・ファセット検索・絞り込みフィルタ
- 検索結果における本文抜粋の表示
- 多言語対応
- 埋め込みベクトル生成ジョブ失敗の画面通知・ジョブ管理用UI（mission_control-jobs 等）の導入

## 7. 今後の拡張予定

本デモは技術記事の題材を主目的とするため、ファーストリリース以降の継続的な拡張は想定しない。記事化の過程で言及される将来的な発展方向（RAG連携、ハイブリッド検索、スケール対応等）は記事内で参考情報として触れることを想定する。
